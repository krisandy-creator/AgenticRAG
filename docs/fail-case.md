# 逐阶段追踪

  ## 阶段1 — 检索（正常）

  BM25 + 向量双路召回 → RRF 融合 → 命中包含 "80mm" 的 chunk。到此为止正常。

  ## 阶段2 — Query Expansion 产生的 structured_intent

  _extract_actions 从问题中只提取到 ["多少"]，_extract_target 把整个问题当 target，entities 是垃圾
  n-gram（"还要继续"、"推多少距"）。这些字段直接喂给后续的 _intent_score 计算。

  ## 阶段3 — EvidenceSelector._intent_score（核心故障点）

  这是分数暴跌发生的地方。_intent_score（evidence_selection.py:130-170）计算问题与 chunk 的字符 n-gram 词法重叠。

  问题的 n-gram 特征（来自 "在泡沫切断规则中每次切断后还要继续推多少距离"）：
  - 包含 "多少"、"距离"、"少距"、"推多"、"往前" 等疑问/泛指词
  - 不包含任何数值（问题在"问"数值，而非"含"数值）

  证据 chunk 的 n-gram 特征（来自 "泡沫切断机构…完成切断后…继续推动80mm…"）：
  - 包含 "80mm"（具体数值）、"推动"、"机构"、"夹具" 等陈述词
  - 不包含 "多少"、"距离"

  重叠的 n-gram仅有话题词："泡沫"、"切断"、"断后"、"继续"、"续推" 等约 7-11 个。

  overlap ≈ 7~11 / sqrt(58 × 117) ≈ 0.03~0.13
  title_bonus = 0.35 × (标题"泡沫供料~粘贴流程"与问题的重叠) ≈ 0.01
  exact_bonus = 0（问题的 target 完整句子不出现在 chunk 中）

  intent_score ≈ 0.03~0.15

  你看到的 0.0318 就是这个 intent_score（或非常接近它的值）。这是一个词法匹配分数的精确计算结果。

  ## 阶段4 — 分数被覆盖

  ### evidence_selection.py:117
  combined = 0.45 × hit.score + 0.55 × intent_score

  即使原始检索分（RRF）为 0.85：
  combined = 0.45 × 0.85 + 0.55 × 0.0318 = 0.3825 + 0.0175 = 0.40

  分数从 0.85 → 0.40，被其他有更多词汇重叠的 chunk 反超（比如包含"切断""规则""距离"等词的 chunk，即使它们不包含 80mm）。

  ## 阶段5 — MMR 多样性选择

  _mmr_select 以 top_k=6 选取。如果正确 chunk 在 intent 重排后掉到第 7+ 名，它直接被丢弃，到不了 LLM。

  即使勉强进入 top 6，它排在末尾，LLM 在 prompt 中看到的是按 rank 排列的证据，排最后面的证据受关注度最低。

  ## 阶段6 — LLM 回答

  如果 chunk 到了 prompt，LLM 看到：
  - 问题："还要继续推多少距离"
  - 证据："需要将材料往继续推动 80mm"

  问题用"多少距离"发问，证据以"80mm"作答——这对人类是等价表达，但对 LLM 来说，如果 prompt
  引导它过度谨慎（"如果证据不足，请明确说明缺少哪些信息"），它可能认为 "80mm" 没有直接回答"多少距离"而输出"证据不足"。

  │ "还要再往前多送多少距离" │ 多送、多少、距离、往前 │ 80mm、推动、继续 │ 仅 "泡沫""切断""断后"                │
  ├──────────────────────────┼────────────────────────┼──────────────────┼──────────────────────────────────────┤

  └──────────────────────────┴────────────────────────┴──────────────────┴──────────────────────────────────────┘

  第二个查询虽然多了 "继续""续推" 的匹配，但"多少""距离"与"80mm"的鸿沟依然存在。intent_score 从 ~0.02 提升到
  ~0.03，不足以改变排序结果。

  # 本质问题

  这是一个用词法匹配（n-gram overlap）替代语义匹配（question-answer pair）的设计缺陷。 事实型 QA
  的核心特征是：问题用疑问词（多少、什么、几…），答案用具体值（80mm、3 个、2024
  年…）。两者在词法层面天然正交，不可能通过 n-gram 重叠来建立关联。

  _intent_score 的设计思想是"与问题词汇越像的 chunk
  越相关"，这对论述型问题有效，但对数值事实型问题完全失效——包含正确答案的 chunk 恰恰是与问题词汇最不像的那个。
